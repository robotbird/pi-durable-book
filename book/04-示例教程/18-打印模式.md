# 示例 18 · 打印模式

> **原文**：[`test/examples/18-print.ts`](../../original/packages/durable/test/examples/18-print.ts)（在 original/packages/durable 目录下运行）
>
> ```bash
> node --conditions=source --experimental-strip-types test/examples/18-print.ts "What is in this directory?"
> ```

## 本例演示

README 把这个例子描述为 "Print mode: submit a prompt, print the answer"——等价于 `pi -p` 的一次性问答模式：从命令行参数取一个提示词，提交、等待、把回答打印到终端就退出。它演示了双模型回落（有 `OPENAI_API_KEY` 用 OpenAI，否则用脚本化 faux 模型）、在扩展里内联声明工具（`createReadTool`/`createBashTool`），以及"宿主只等待自己的 Submission，不等全局空闲"的用法。

## 逐段解读

### 头部：打印模式的定义

```ts
// Print mode: submit one prompt and print its answer, like `pi -p`. The host awaits its own Submission, not global
// idle. Uses OpenAI when OPENAI_API_KEY is set, and a scripted faux model otherwise.
// Run from packages/durable:
//   node --conditions=source --experimental-strip-types test/examples/18-print.ts "What is in this directory?"
import { BACKGROUND_CONTEXT } from "@earendil-works/chord/context";
import type { AssistantMessage } from "@earendil-works/pi-ai";
import { createModels } from "@earendil-works/pi-ai/models";
import { fauxAssistantMessage, fauxProvider, fauxText, fauxToolCall } from "@earendil-works/pi-ai/providers/faux";
import { openaiProvider } from "@earendil-works/pi-ai/providers/openai";
import { NodeExecutionEnv } from "../../src/env/node.ts";
import { AssistantEntry, createRegistry, defineExtension, Harness, MemoryStorage, section } from "../../src/index.ts";
import { createBashTool, createReadTool } from "../../src/tools/index.ts";

const context = BACKGROUND_CONTEXT;
const prompt = process.argv[2] ?? "What is in this directory?";
```

头部注释给出本例的两个要点：打印模式提交一个提示、打印回答（类似 `pi -p`）；**宿主等待的是自己的 Submission，而不是全局空闲**。提示词从 `process.argv[2]` 读取，没传就用默认值。

### 双模型回落：有 key 用 OpenAI，没有就用 faux

```ts
const models = createModels();
let model = { provider: "openai", modelId: "gpt-6-sol" };
if (process.env.OPENAI_API_KEY !== undefined) {
	models.setProvider(openaiProvider());
} else {
	const faux = fauxProvider();
	models.setProvider(faux.provider);
	model = { provider: "faux", modelId: "faux-1" };
	faux.setResponses([
		fauxAssistantMessage([fauxToolCall("bash", { command: "ls" }, { id: "call-1" })], { stopReason: "toolUse" }),
		fauxAssistantMessage([fauxText("This directory holds the durable package sources, tests, and docs.")]),
	]);
}
```

设了 `OPENAI_API_KEY` 就注册 OpenAI provider、用 `gpt-6-sol`；否则切到 faux 模型，并预置两步剧本：先发起一次 `bash ls` 工具调用（`stopReason: "toolUse"`），拿到结果后再给出文字回答——这样即便离线，示例也能完整走过"工具调用 → 回答"的流程。

### 在扩展里内联声明工具

```ts
const registry = createRegistry();
registry.install(
	defineExtension({
		name: "coding",
		tools: [createReadTool(), createBashTool()],
		sections: [section("preamble", () => "You are a concise coding assistant.", { tag: false })],
	}),
);
const env = new NodeExecutionEnv({ cwd: process.cwd() });
const harness = await Harness.open(new MemoryStorage(), { models, registry, env: () => env }, context);
const root = await harness.root(context, { agent: { model } });
```

上一个示例用的是整包的 `CodingTools`，这里换成在扩展的 `tools` 数组里用工厂函数**内联声明**需要的工具：`createReadTool()` 和 `createBashTool()`，同时照常提供一个 `preamble` 系统提示 section。执行环境是固定在进程 cwd 的单个 `NodeExecutionEnv`，通过 `env: () => env` 让每次调用复用同一个实例。

### 提交、等待、打印、退出

```ts
const submission = await root.submit({ type: "input", content: prompt }, context);
const settled = await submission.wait(context);
if (settled.status === "done" && settled.type === "input") {
	const entry = await root.commit((tx) => tx.entry(AssistantEntry, settled.answer), context);
	const answer = entry?.model?.[0] as AssistantMessage;
	console.log(answer.content.flatMap((content) => (content.type === "text" ? [content.text] : [])).join(""));
} else {
	console.error(`unanswered: ${settled.status === "unanswered" ? settled.reason : settled.status}`);
	process.exitCode = 1;
}
await harness.close(context);
```

标准四步：`submit` 受理输入 → `wait` 等回答 → `commit` 把回答写成 `AssistantEntry` → 从消息内容里抽取所有文本块拼接打印。注意这里**没有**调用 `harness.waitForIdle()`——打印模式只关心自己这一问的 Submission，等它落定即可。回答失败时把原因写到 stderr，并设置 `process.exitCode = 1` 让进程以非零码退出，符合命令行工具的习惯。

## 关键点

- 打印模式是一次性问答 CLI 的骨架：读 argv → `submit` → `wait` → `commit` → 打印文本 → `close` 退出，不维护多轮会话。
- "宿主等待自己的 Submission，而非全局空闲"：对比下一个示例（JSON 模式）提交后还要 `waitForIdle`——打印模式只需要自己的答案。
- 有 `OPENAI_API_KEY` 用真实 OpenAI 模型，没有就回落到脚本化 faux 模型，示例在任何环境都能跑通。
- 工具可以在扩展里用工厂函数按需内联声明（`createReadTool()`、`createBashTool()`），不必安装整包 `CodingTools`；执行环境可通过 `env: () => env` 复用同一个实例。
- 回答不会自动落盘：`wait()` 返回 `done` 后由宿主决定 `commit` 成 `AssistantEntry`，再从 `AssistantMessage.content` 里筛出文本块打印。
- 失败路径也要处理：`unanswered` 时打印 `reason` 并设 `process.exitCode = 1`，这是 CLI 集成的标准做法。
