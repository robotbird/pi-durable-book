# 示例 27 · 计划模式

> **原文**：[`test/examples/27-plan-mode.ts`](https://github.com/earendil-works/pi/blob/main/packages/durable/test/examples/27-plan-mode.ts)（在原仓库 `packages/durable` 目录下运行）
>
> ```bash
> node --conditions=source --experimental-strip-types test/examples/27-plan-mode.ts
> ```

## 本例演示

用"扩展 + 工具选择"实现一个只读的计划模式：进入模式就是一次 `configure()`——追加 Plan 扩展、把工具收窄为 read 和 submit_plan；模型把计划写进扩展自己的 `PlanDoc` 文档；退出模式用两个 `null` 清空覆盖、恢复宿主默认的全部工具。最后回放转录，看模型眼中的模式切换：一条条带 `sections`/`toolsAdded`/`toolsRemoved` 的系统提示变化消息。

## 逐段解读

### 产品代码：计划文档与提交计划工具

```ts
import { mkdtemp, rm, writeFile } from "node:fs/promises";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { BACKGROUND_CONTEXT } from "@earendil-works/chord/context";
import { Type } from "@earendil-works/pi-ai";
import { createModels } from "@earendil-works/pi-ai/models";
import { fauxAssistantMessage, fauxProvider, fauxToolCall } from "@earendil-works/pi-ai/providers/faux";
import { NodeExecutionEnv } from "../../src/env/node.ts";
import {
	createRegistry,
	defineDoc,
	defineExtension,
	defineTool,
	Harness,
	MemoryStorage,
	section,
} from "../../src/index.ts";
import { CodingTools, createReadTool } from "../../src/tools/index.ts";

const context = BACKGROUND_CONTEXT;

// ─── Product code: the plan extension ───────────────────────────────────────

// The current plan of a conversation. A fork keeps the plan it had at the fork entry.
const PlanDoc = defineDoc<{ steps: string[] }>({
	kind: "app.plan",
	version: 1,
	scope: "conversation",
	history: "rewindable",
	fork: "asOf",
	initial: () => ({ steps: [] }),
});

const submitPlan = defineTool({
	name: "submit_plan",
	description: "Submit the plan as a list of steps.",
	parameters: Type.Object({ steps: Type.Array(Type.String()) }),
	execute: async (args, api, callContext) => {
		await api.commit(async (tx) => {
			(await tx.doc(PlanDoc, api.conversationId)).steps = args.steps;
		}, callContext);
		return { content: [{ type: "text", text: "Plan submitted." }], control: { terminate: true } };
	},
});

const Plan = defineExtension({
	name: "plan",
	tools: [submitPlan],
	sections: [
		section("plan_mode", () => "You are in plan mode. Read the code, then call submit_plan. Change nothing."),
	],
});
```

`PlanDoc` 存对话当前的计划：`scope: "conversation"` 每个对话一份；`history: "rewindable"` 可以回退；`fork: "asOf"` 的语义由注释给出——分叉出的对话保留**分叉点当时**的计划。`submit_plan` 工具用 `Type.Object` 声明参数 schema；`execute` 里通过 `api.commit` 加 `tx.doc(PlanDoc, api.conversationId)` 把步骤写进文档，返回值除了给模型的确认文本，还带 `control: { terminate: true }`——交了计划就结束本轮。`Plan` 扩展把这个工具和一段"你在计划模式：只读代码、调用 submit_plan、什么都别改"的提示词打包在一起。

### 进/出计划模式就是两次 configure

```ts
// Plan mode is a change to the conversation's agent: select the plan extension and offer only reading and
// submitting. Clearing both returns to the host's default selection and every tool.
const read = createReadTool();
const enterPlanMode = { extensions: { add: [Plan] }, tools: [read, submitPlan] };
const leavePlanMode = { extensions: null, tools: null };
```

注释给出定义：计划模式只是对对话 agent 配置的一次修改——追加 Plan 扩展，并把工具列表收窄为"只读 + 提交计划"。`tools: [read, submitPlan]` 是**整体覆盖**：此刻模型手里只有这两个工具（`createReadTool()` 单独造一个只读工具实例）。退出更简单：两个字段都置 `null`，清空这层覆盖，回到宿主默认的扩展选择和全部工具——不需要把"进入时改了什么"逆向描述一遍。

### 宿主：默认只选 CodingTools

```ts
// ─── Host setup ─────────────────────────────────────────────────────────────

const directory = await mkdtemp(join(tmpdir(), "pi-durable-plan-"));
await writeFile(join(directory, "server.ts"), "app.listen(3000);\n");

const faux = fauxProvider();
const models = createModels();
models.setProvider(faux.provider);
faux.setResponses([
	fauxAssistantMessage(fauxToolCall("read", { path: "server.ts" }), { stopReason: "toolUse" }),
	fauxAssistantMessage(fauxToolCall("submit_plan", { steps: ["Read PORT from the environment", "Default to 3000"] }), {
		stopReason: "toolUse",
	}),
	fauxAssistantMessage("Implementing step 1."),
]);

const registry = createRegistry();
registry.install(CodingTools);
registry.install(Plan);
const harness = await Harness.open(
	new MemoryStorage(),
	// Installed, but only CodingTools is selected by default: conversations opt into plan mode.
	{ models, registry, settings: { extensions: [CodingTools] }, env: () => new NodeExecutionEnv({ cwd: directory }) },
	context,
);
const root = await harness.root(context, { agent: { model: { provider: "faux", modelId: "faux-1" } } });
const tools = async () => (await root.agent(context)).tools.map((tool) => tool.name);
console.log("tools:", await tools());
```

工作目录里放一个 `server.ts`（端口写死 3000），计划的主题就是"让端口可配置"。模型剧本三步：`read server.ts` → `submit_plan` 提交两个步骤 → 退出模式后回答 "Implementing step 1."。注意 settings 行的注释：Plan **已安装**但默认选择里只有 CodingTools——安装进注册表不等于选中，是否启用计划模式由每个对话自己 opt-in。`root.agent(context)` 返回对话当前生效的 agent 视图，`tools()` 辅助函数打印工具名列表，第一行输出是默认工具集。

### 进入计划模式，读代码、交计划

```ts
await root.configure(enterPlanMode, context);
console.log("plan mode tools:", await tools());
await (await root.submit({ type: "input", content: "Make the port configurable." }, context)).wait(context);
console.log("plan:", (await harness.snapshot(PlanDoc, root.id, context))?.steps);
```

`configure(enterPlanMode)` 后工具列表收窄为 `read` 和 `submit_plan`。随后一轮对话：模型读到 `server.ts`，调用 `submit_plan` 提交两个步骤——`harness.snapshot(PlanDoc, root.id)` 从对话文档里读出计划并打印，即 `["Read PORT from the environment", "Default to 3000"]`。

### 退出计划模式与系统提示回放

```ts
await root.configure(leavePlanMode, context);
console.log("tools again:", await tools());
await (await root.submit({ type: "input", content: "Go ahead." }, context)).wait(context);

// The model saw each switch as a system prompt change in its transcript.
const { messages } = await root.context(context);
for (const message of messages) {
	if (message.role !== "system") continue;
	console.log("system:", {
		// A null section value removes it.
		sections: message.sections,
		added: message.toolsAdded?.map((tool) => tool.name),
		removed: message.toolsRemoved?.map((tool) => tool.name),
	});
}

await harness.close(context);
await rm(directory, { recursive: true, force: true });
```

`configure(leavePlanMode)` 清空覆盖，工具恢复完整，模型随后正常开始实现（"Implementing step 1."）。最后按注释回放转录：**模型把每次切换都看成一条系统提示的变化消息**——逐条打印 system 消息的 `sections`（`plan_mode` 段的加入与移除；行内注释提醒：段值为 `null` 表示该段被删除）、`toolsAdded` 与 `toolsRemoved`（进出模式时工具集的增删）。这就是模式切换对模型的全部可见形式。最后清理临时目录。

## 关键点

- 计划模式不是开关字段，而是一次 `configure()`：`{ extensions: { add: [Plan] }, tools: [read, submitPlan] }` 追加扩展并把工具列表整体收窄。
- `{ extensions: null, tools: null }` 清空覆盖层、回到宿主默认选择——"退出"无需逆向描述进入时的改动。
- 安装 ≠ 选中：`settings.extensions` 默认只有 CodingTools，扩展按对话 opt-in。
- `defineDoc` 的 `fork: "asOf"` 让分叉保留分叉点时的计划；`history: "rewindable"` 支持回退。
- 工具可以在 `execute` 里 `api.commit` + `tx.doc()` 写对话文档，并返回 `control: { terminate: true }` 结束回合。
- 模型看到的模式切换 = 转录里的 system 消息（`sections` 变化、`toolsAdded`/`toolsRemoved`；段值为 null 表示删除）。
