# 示例 00 · 会话与对话

> **原文**：[`test/examples/00-conversation.ts`](https://github.com/earendil-works/pi/blob/main/packages/durable/test/examples/00-conversation.ts)（在原仓库 `packages/durable` 目录下运行）
>
> ```bash
> node --conditions=source --experimental-strip-types test/examples/00-conversation.ts
> ```

## 本例演示

这是整个示例系列的最小入口：创建一个 Session，在一个事务里创建一条新的会话（conversation），然后关闭。代码只有寥寥几行，却引出了贯穿所有示例的基础概念——`createSession` 与 `MemoryStorage`、用于取消控制的 `context`、以 `session.commit()` 包裹的事务式写入，以及会话的 `ownership`（归属）。

## 逐段解读

### 1. 创建会话存储

```ts
// A Session stores conversations, transcript entries, tasks, and documents.
// Run from packages/durable:
//   node --conditions=source --experimental-strip-types test/examples/00-conversation.ts
import { BACKGROUND_CONTEXT } from "@earendil-works/chord/context";
import { createSession, MemoryStorage } from "../../src/index.ts";

// MemoryStorage keeps everything in memory; other storage backends keep it on disk.
const session = createSession(new MemoryStorage());
```

开头注释点明了 Session 的职责：它存储会话、转录条目（transcript entries）、任务和文档。`MemoryStorage` 把所有数据都保存在内存里（适合示例和测试）；换成其他存储后端时数据会写到磁盘，而上层的调用代码不需要任何改动。

### 2. 取消上下文

```ts
// Every Session call takes a context, which is used for cancellation.
// BACKGROUND_CONTEXT means "never cancel".
const context = BACKGROUND_CONTEXT;
```

Session 的每个调用都要传入一个 context，用于取消（cancellation）正在进行的操作；`BACKGROUND_CONTEXT` 的含义是"永不取消"。示例用它来省去真正的取消逻辑，后续示例都会沿用这个写法。

### 3. 在事务里创建会话

```ts
// All writes happen inside session.commit(). The callback receives a
// transaction `tx`; everything it writes is saved together when the callback
// returns, or discarded if it throws.
// "ownerless" means no task created this conversation.
const standalone = await session.commit((tx) => tx.createConversation({ ownership: { kind: "ownerless" } }), context);
console.log("standalone conversation:", standalone);

await session.close(context);
```

所有写操作都必须发生在 `session.commit()` 的事务回调里：回调拿到一个事务对象 `tx`，回调正常返回时它写入的所有内容一起保存，抛出异常则全部丢弃——这就是写入的原子性来源。这里用 `tx.createConversation()` 创建了一条 `ownerless`（无主）会话，意思是它不是由任何任务创建的，是一条独立会话。最后调用 `session.close()` 释放资源。

## 关键点

- `Session` 是一切操作的入口：`createSession(new MemoryStorage())`；`MemoryStorage` 纯内存，生产环境可换其他后端，接口不变。
- 所有写入都必须包在 `session.commit()` 的事务回调中，回调整体提交或整体回滚。
- 每个 Session 调用都携带一个取消用的 `context`；`BACKGROUND_CONTEXT` 表示永不取消。
- `ownership: { kind: "ownerless" }` 表示无主会话；后续示例会看到 `task`、`conversation` 等其他归属形态。
- 用完记得 `session.close(context)`。
