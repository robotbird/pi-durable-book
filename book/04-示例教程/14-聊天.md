# 示例 14 · 聊天

> **原文**：[`test/examples/14-chat.ts`](https://github.com/earendil-works/pi/blob/main/packages/durable/test/examples/14-chat.ts)（在原仓库 `packages/durable` 目录下运行）
>
> ```bash
> node --conditions=source --experimental-strip-types test/examples/14-chat.ts
> ```

## 本例演示

项目 README 把这个例子描述为 "One question and answer"（一问一答）——它是 pi-durable 里最基础的完整示例：提交一个用户输入，等待内置生成任务调用模型并产出回答，再把回答写入对话记录，最后打印记录内容。看懂它，就掌握了与对话交互的最小闭环。

## 逐段解读

### 用 faux 假模型代替真实模型

```ts
// A chat turn.
// Run from packages/durable:
//   node --conditions=source --experimental-strip-types test/examples/14-chat.ts
import { BACKGROUND_CONTEXT } from "@earendil-works/chord/context";
import { createModels } from "@earendil-works/pi-ai/models";
import { fauxAssistantMessage, fauxProvider } from "@earendil-works/pi-ai/providers/faux";
import { AssistantEntry, createRegistry, defineExtension, Harness, MemoryStorage, section } from "../../src/index.ts";

const context = BACKGROUND_CONTEXT;

// The faux provider stands in for a real model (see 16-real-model.ts).
const faux = fauxProvider();
const models = createModels();
models.setProvider(faux.provider);
faux.setResponses([fauxAssistantMessage("Paris.")]);
```

注释说明 faux 供应商是真实模型的替身（想接真模型参见 16-real-model.ts）：把它注册进模型表，再用 `setResponses` 预设好模型要"说"的话——问法国首都，答 "Paris."。这样示例可以离线跑通完整流程。

### 一个只带系统提示的极简扩展

```ts
const registry = createRegistry();
registry.install(
	defineExtension({
		name: "terse",
		sections: [section("preamble", () => "You answer in one word.", { tag: false })],
	}),
);
const harness = await Harness.open(new MemoryStorage(), { models, registry }, context);
const root = await harness.root(context, { agent: { model: { provider: "faux", modelId: "faux-1" } } });
```

扩展 `terse` 只提供一个 `preamble` section：渲染函数返回一句固定的系统提示"你用一个词回答"。`{ tag: false }` 表示这段文本原样发送，不包上默认的 `<preamble>...</preamble>` 标签。根对话创建时把 agent 模型指定为 faux 的 `faux-1`。

### 提问、等待、落盘

```ts
// submit() durably admits user input and returns a Submission. The built-in
// pi.generation task prepares the system prompt from the agent's sections,
// calls the model, and appends the answer; wait() resolves once the input is
// answered or has failed.
const capital = await root.submit({ type: "input", content: "Capital of France?" }, context);
const answered = await capital.wait(context);
if (answered.status === "done" && answered.type === "input") {
	const entry = await root.commit((tx) => tx.entry(AssistantEntry, answered.answer), context);
	const reply = entry?.model?.[0];
	console.log("answer:", reply?.role === "assistant" ? reply.content : reply);
}
```

注释把一次聊天的内部机制讲得很清楚：`submit()` **持久化地受理**（durably admit）用户输入并返回一个 Submission——输入先落盘，崩溃也不会丢；真正干活的是内置的 `pi.generation` 任务，它从 agent 各扩展的 sections 准备系统提示、调用模型、追加答案。`wait()` 在输入被回答或失败后 resolve。回答并不会自动写进记录：示例先检查 `answered.status === "done"` 且类型是 `input`，然后由应用自己 `commit`——`tx.entry(AssistantEntry, answered.answer)` 把生成结果写成一条助手条目，最后从 `entry.model[0]` 里取出助手消息打印。

### 查看记录里留下了什么

```ts
// The transcript holds the user input, the positional system prompt, and the answer.
const transcript = await root.entries({}, 10, undefined, context);
console.log(
	"transcript:",
	[...transcript.items].reverse().map((entry) => entry.kind),
);
await harness.close(context);
```

`entries()` 按最新在前分页读出记录，反转后打印条目种类。注释点明一次问答会在记录里留下三类条目：用户输入、**位置式系统提示**（positional system prompt，系统提示作为记录的一部分持久保存）、以及回答。

## 关键点

- 这是"一问一答"的最小完整示例：`submit()` → `wait()` → `commit` 回答，三步构成与对话交互的基本闭环。
- `submit()` 先把用户输入持久化受理再返回 Submission，崩溃后输入也不会丢；生成由内置 `pi.generation` 任务完成。
- `wait()` resolve 时拿到的是生成结果，写入记录（`tx.entry(AssistantEntry, ...)`）是应用自己的决定——要不要落盘、何时落盘由你控制。
- 系统提示来自 agent 所选扩展的 sections，随工具一起进入对话；`{ tag: false }` 让 section 文本不加标签原样发送。
- faux 供应商 + `setResponses` 让示例无需网络即可测试完整轮次；接真实模型换掉 provider 即可（见 16-real-model.ts）。
- `root.entries({}, 10, undefined, context)` 分页读取记录（最新在前），是检查"存储里到底有什么"的常用手段。
