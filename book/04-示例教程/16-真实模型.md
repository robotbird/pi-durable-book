# 示例 16 · 真实模型

> **原文**：[`test/examples/16-real-model.ts`](https://github.com/earendil-works/pi/blob/main/packages/durable/test/examples/16-real-model.ts)（在原仓库 `packages/durable` 目录下运行）
>
> ```bash
> node --conditions=source --experimental-strip-types test/examples/16-real-model.ts
> ```

## 本例演示

README 把这个例子描述为 "Streaming an answer from OpenAI"——前几个示例都用 faux 假模型离线跑流程，本例第一次接入真实模型：从 OpenAI 流式生成一段长诗。它演示了三件事：如何把真实 provider 装配进 Harness（`createModels` + `openaiProvider`）；如何监听对话的 `pi.live` 文档把"已提交的流式部分"实时打印出来；以及如何用最终提交的回答补上流式打印的尾巴。没有 `OPENAI_API_KEY` 时整个示例会打印提示并跳过。

## 逐段解读

### 头部：说明与导入

```ts
// A real model: stream an answer from OpenAI.
// Run from packages/durable (needs OPENAI_API_KEY):
//   node --conditions=source --experimental-strip-types test/examples/16-real-model.ts
import { BACKGROUND_CONTEXT } from "@earendil-works/chord/context";
import { createModels } from "@earendil-works/pi-ai/models";
import { openaiProvider } from "@earendil-works/pi-ai/providers/openai";
import {
	AssistantEntry,
	createRegistry,
	defineExtension,
	Harness,
	LiveDoc,
	MemoryStorage,
	section,
} from "../../src/index.ts";

const context = BACKGROUND_CONTEXT;
```

头部注释点明：示例需要 `OPENAI_API_KEY`，要在 `packages/durable` 目录下运行。这次导入的是 `openaiProvider` 而不是 faux，还额外引入了 `LiveDoc`——待会儿监听流式输出就靠它。

### 接入真实模型：Harness 与 provider 的唯一接口

```ts
// Production code passes a Models collection with real providers; the Harness
// never talks to a provider any other way. openaiProvider() reads
// OPENAI_API_KEY from the environment. While the answer streams, generation
// commits throttled partials to the conversation's pi.live document. Watching
// that document streams the answer; the watch sees only committed values.
if (process.env.OPENAI_API_KEY === undefined) {
	console.log("skipped: OPENAI_API_KEY is not set");
} else {
	const models = createModels();
	models.setProvider(openaiProvider());
```

这段英文注释是本例的核心机制说明：生产代码把带真实 provider 的 Models 集合传给 Harness——**Harness 除此之外不会以任何方式接触 provider**；`openaiProvider()` 自己从环境变量读取 `OPENAI_API_KEY`。回答流式生成的过程中，generation 会把节流（throttled）后的部分文本提交进对话的 `pi.live` 文档，监听这个文档就能"看到"回答逐渐变长，而且监听者只会看到**已提交**的值（不是每个 token 都实时可见）。没设 key 时打印 skipped 并跳过，示例不会报错。

### 注册表、Harness 与根对话

```ts
	const registry = createRegistry();
	registry.install(
		defineExtension({
			name: "concise",
			sections: [section("preamble", () => "You are a concise assistant.", { tag: false })],
		}),
	);
	const harness = await Harness.open(new MemoryStorage(), { models, registry }, context);
	const root = await harness.root(context, {
		agent: { model: { provider: "openai", modelId: "gpt-6-sol" }, thinkingLevel: "high" },
	});
	const liveWatch = (await harness.watchDoc(LiveDoc, root.id, context))!;
```

扩展 `concise` 只提供一句系统提示。创建根对话时通过 `agent.model` 指定 provider 为 `openai`、模型 `gpt-6-sol`，还设置了 `thinkingLevel: "high"`（思考档位）。`harness.watchDoc(LiveDoc, root.id, context)` 拿到对话 `pi.live` 文档的监听句柄（返回值可能为空，用 `!` 断言存在）——注意监听要在启动运行之前挂好。

### 增量打印：只输出新增的部分

```ts
	// Print only what each committed partial adds to the text printed so far.
	let printed = "";
	const printText = (text: string): void => {
		if (text.length <= printed.length || !text.startsWith(printed)) return;
		process.stdout.write(text.slice(printed.length));
		printed = text;
	};
	liveWatch.start(async (value) => {
		const block = value?.generation?.message?.content.find((content) => content.type === "text");
		if (block?.type === "text") printText(block.text);
	});
```

`printText` 是一个增量打印器：每次回调拿到的都是**完整的当前文本**，它只打印相对已打印前缀新增的尾巴（不是前缀的延伸就忽略）。`liveWatch.start` 的回调从文档值的 `generation.message.content` 里找到文本块交给它——`pi.live` 文档的 `generation` 字段就是当前正在流式生成的消息。

### 启动、提交与等待

```ts
	harness.resume();
	process.stdout.write("answer: ");
	const poem = await root.submit({ type: "input", content: "Write a long poem" }, context);
	const settledPoem = await poem.wait(context);
	await liveWatch.stop();
```

`harness.resume()` 显式唤醒任务调度器（调度器默认暂停，`submit()` 内部也会触发唤醒；这里在监听挂好之后显式调用，确保流式输出从第一个字起就被看到）。然后提交 "Write a long poem"，`wait()` 等它落定，最后停掉监听。

### 补尾巴：最终回答里还有流式没打完的部分

```ts
	if (settledPoem.status === "done" && settledPoem.type === "input") {
		// The last throttle window may not have been committed as a partial; the answer entry has the rest.
		const entry = await root.commit((tx) => tx.entry(AssistantEntry, settledPoem.answer), context);
		const message = entry?.model?.[0];
		const block =
			message?.role === "assistant" ? message.content.find((content) => content.type === "text") : undefined;
		if (block?.type === "text") printText(block.text);
		process.stdout.write("\n");
	} else {
		console.log("unanswered:", settledPoem.reason, settledPoem.detail);
	}
	await harness.close(context);
}
```

注释解释了为什么还要补一刀：**最后一个节流窗口可能没来得及作为部分文本提交**，所以要把生成结果 commit 成 `AssistantEntry`，再从完整回答里取出文本交给同一个 `printText`——因为它是增量的，只会补出还没打印的剩余部分。未回答时打印原因和细节。最后关闭 Harness。

## 关键点

- 真实模型的接入点只有一个：把 `createModels()` 集合（装上 `openaiProvider()` 等 provider）传给 `Harness.open` 的 options，模型在 `harness.root` 的 `agent.model` 里按 `provider + modelId` 选用。
- 流式输出的底层机制：generation 把节流的部分文本**提交**进对话的 `pi.live` 文档，`harness.watchDoc(LiveDoc, ...)` 监听该文档即可获得流式效果，且只会看到已提交的值。
- 回调拿到的是全量文本，前端要自己做增量差分（本例的 `printText` 用前缀比较实现）；最后还需用提交的回答补齐未提交的尾巴。
- 监听要挂在 `resume()`/`submit()` 之前，否则会错过开头的输出；调度器默认暂停，`resume()` 或 `submit()` 都会把它唤醒。
- 回答仍需宿主自己 `commit` 成 `AssistantEntry` 才进入对话记录；失败时 `wait()` 返回的记录带 `reason` 和 `detail`。
- 本例也演示了 `thinkingLevel: "high"` 的配置方式，以及"没有 API key 就优雅跳过"的示例写法。
