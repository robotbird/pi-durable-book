# 示例 21 · 中途加入

> **原文**：[`test/examples/21-late-join.ts`](../../original/packages/durable/test/examples/21-late-join.ts)（在 original/packages/durable 目录下运行）
>
> ```bash
> node --conditions=source --experimental-strip-types test/examples/21-late-join.ts
> ```

## 本例演示

README 把这个例子描述为 "Attaching a view and an event stream mid-run"——运行已经开始，客户端才接入：它先拿到**当前完整状态**（对话视图或 snapshot 事件），之后只接收增量变化。示例安排一个每 100ms 输出一行的慢工具加一个缓慢流式的回答，在工具跑到一半时让两种客户端加入：结构化客户端（`viewState` + `subscribe`）和事件客户端（`watchEvents`），对照展示同一状态的两种读法。

## 逐段解读

### 一个会慢慢输出的工具

```ts
// Late join: a client attaches while a run is already underway. It gets the current state first, the conversation
// view or the snapshot event, and then only what changes after that.
// Run from packages/durable:
//   node --conditions=source --experimental-strip-types test/examples/21-late-join.ts
import { BACKGROUND_CONTEXT } from "@earendil-works/chord/context";
import { Type } from "@earendil-works/pi-ai";
import { createModels } from "@earendil-works/pi-ai/models";
import { fauxAssistantMessage, fauxProvider, fauxText, fauxToolCall } from "@earendil-works/pi-ai/providers/faux";
import {
	type AgentEvent,
	createRegistry,
	defineExtension,
	defineTool,
	Harness,
	type LiveState,
	MemoryStorage,
	watchEvents,
} from "../../src/index.ts";

const context = BACKGROUND_CONTEXT;
const pause = (ms: number) => new Promise((resolve) => setTimeout(resolve, ms));

// A tool that prints a line every 100 ms, then a slowly streamed answer.
const registry = createRegistry();
registry.install(
	defineExtension({
		name: "count",
		tools: [
			defineTool({
				name: "count",
				description: "Counts to ten",
				parameters: Type.Object({}),
				execute: async (_args, api) => {
					for (let n = 1; n <= 10; n++) {
						api.output(`${n}\n`);
						await pause(100);
					}
					return {};
				},
			}),
		],
	}),
);
```

`count` 工具每 100ms 用 `api.output()` 追加一行数字、共数到十——`api.output()` 写入工具的**实时输出槽**，监听者能看着它逐渐增长，为"中途加入"提供了可观察的动态状态。参数用 `Type.Object({})` 声明为空对象。

### 慢流式模型与中途提交

```ts
const faux = fauxProvider({ tokensPerSecond: 40, tokenSize: { min: 1, max: 1 } });
faux.setResponses([
	fauxAssistantMessage([fauxToolCall("count", {}, { id: "call-1" })], { stopReason: "toolUse" }),
	fauxAssistantMessage([fauxText("Counted to ten, and this answer streams slowly.")]),
]);
const models = createModels();
models.setProvider(faux.provider);
const harness = await Harness.open(new MemoryStorage(), { models, registry }, context);
const root = await harness.root(context, { agent: { model: { provider: "faux", modelId: "faux-1" } } });

const submission = await root.submit({ type: "input", content: "Count to ten, then tell me." }, context);
// Join while the tool is halfway through.
await pause(500);
```

faux 配置成每秒 40 个 token、且 `tokenSize: { min: 1, max: 1 }`（每次恰好一个 token）——回答会一格一格地慢慢流出。剧本先调用 `count` 工具，再给一个缓慢流式的回答。提交后只等 500ms（工具每 100ms 数一个数，此时正好数到约第 5 个），然后在工具跑到一半时加入。

### 结构化客户端：视图优先

```ts
// Structural client: the view holds the committed transcript and documents, including the running tool's output.
const view = await root.viewState(context);
const live = view.value.docs["pi.live"] as LiveState;
console.log(
	"view entries:",
	view.value.entries.map((entry) => entry.kind),
);
console.log("view tool slot:", live.tools?.[0]?.status, JSON.stringify(live.tools?.[0]?.output));
view.subscribe((value) => {
	const slot = (value.docs["pi.live"] as LiveState).tools?.[0];
	if (slot?.status === "running") console.log("view output now:", JSON.stringify(slot.output));
});
```

结构化客户端用 `root.viewState()` 一次拿到**已提交的完整视图**：记录列表加上所有文档——包括正在运行的工具的输出槽（`pi.live` 文档的 `tools[0]`，能看到 status 和已输出的数字）。之后 `view.subscribe()` 订阅视图变化，回调里继续从最新视图读工具输出槽的增量内容。

### 事件客户端：快照 + 事件流

```ts
// Event client: the snapshot event carries the same state; later events apply on top of it.
const stream = await watchEvents(harness, root.id, context);
console.log(
	"snapshot tools:",
	stream.snapshot.tools.map((slot) => `${slot.name} ${slot.status}`),
);
let output = stream.snapshot.tools[0]?.output ?? "";
stream.start(async (events: readonly AgentEvent[]) => {
	for (const event of events) {
		if (event.type === "tool_execution_update" && event.output !== undefined) {
			output =
				"set" in event.output
					? event.output.set
					: output.slice(event.output.trimStart ?? 0) + (event.output.append ?? "");
			console.log("event output now:", JSON.stringify(output));
		} else if (event.type === "message_update") {
			const deltas = event.changes.flatMap((change) => (change.type === "text_delta" ? [change.delta] : []));
			console.log("event text delta:", JSON.stringify(deltas.join("")));
		} else {
			console.log("event:", event.type);
		}
	}
});
```

事件客户端的 `watchEvents()` 返回的流自带 `snapshot`——它携带与视图**相同的现状**（含运行中工具的槽），之后的事件在其上叠加。回调演示了三类事件的处理：`tool_execution_update` 的输出要么整体 `set`，要么是增量 `{ trimStart, append }`（先裁掉本地副本的前 `trimStart` 个字符再追加），客户端据此维护本地副本；`message_update` 携带 `text_delta` 文本增量，用于流式渲染回答；其余事件只打印类型。

### 收尾

```ts
await submission.wait(context);
await harness.waitForIdle(context);
await pause(0);
await stream.stop();
view.dispose();
await harness.close(context);
```

等提交落定、等全局空闲，再让事件循环转一圈让最后一批回调跑完，然后停掉事件流、释放视图订阅（`view.dispose()`）、关闭 Harness。

## 关键点

- 中途加入的客户端先拿完整现状（视图或 snapshot 事件），之后只收增量——不需要重放历史事件，这是"迟到不丢状态"的关键设计。
- 两种客户端形态可对照使用：结构化的 `root.viewState()` + `subscribe()` 直接读视图里的记录与文档；事件型的 `watchEvents()` 以 `snapshot` 起步、逐批接收 `AgentEvent`。
- 工具内 `api.output()` 实时更新 `pi.live` 文档里的工具输出槽，两种客户端都能看到它增长——运行中状态对迟到者可见。
- `tool_execution_update` 事件的输出有两种形态：整体 `set` 或增量 `{ trimStart, append }`，客户端要同时处理两者才能正确维护本地副本。
- `message_update` 事件里的 `text_delta` 是流式渲染回答文本的来源，与前面示例里监听 `pi.live` 文档的效果等价，但粒度更细。
- `fauxProvider({ tokensPerSecond, tokenSize: { min: 1, max: 1 } })` 可以精确控制假模型的流式节奏，方便制造可预测的"运行中"场景。
