> ```bash

## 本例演示

用 watch（观察器）串行化对文档的异步处理。`session.watchDoc()` 创建一个从"一次稳定获取修订"出发的观察器，`start()` 注册异步回调；提交一次文档修改后，回调被异步调用，示例用 Promise 等到这次投递完成后 `stop()` 收尾。关键 API：`session.watchDoc`、`notesWatch.start`、`notesWatch.stop`。

## 逐段解读

### 1. 准备

```ts
// Serialize asynchronous document work with a watch.
// Run from packages/durable:
//   node --conditions=source --experimental-strip-types test/examples/05-watches.ts
import { BACKGROUND_CONTEXT } from "@earendil-works/chord/context";
import { createSession, defineDoc, MemoryStorage } from "../../src/index.ts";

const context = BACKGROUND_CONTEXT;
const session = createSession(new MemoryStorage());

const Notes = defineDoc<{ text: string }>({
	kind: "example.notes",
	version: 1,
	scope: "conversation",
	history: "rewindable",
	fork: "asOf",
	initial: () => ({ text: "" }),
});
const chat = await session.commit(async (tx) => {
	const conversation = await tx.createConversation({ ownership: { kind: "ownerless" } });
	(await tx.doc(Notes, conversation.id)).text = "first";
	return conversation;
}, context);
```

准备与示例 04 相同：定义 Notes 文档，并在创建会话的同一事务里写入 "first"，让文档从诞生起就有确定的值。

### 2. 创建观察器并启动回调

```ts
// A watch starts from one stable acquisition revision. Slow callbacks never
// overlap; exact committed frames buffer, with a full-value reset after 100.
const notesWatch = await session.watchDoc(Notes, chat.id, context);
if (notesWatch === undefined) throw new Error("notes are absent");
console.log("watch baseline:", notesWatch.value);
const delivered = new Promise<void>((resolve) => {
	notesWatch.start(async (value, _ops, _deliveryContext) => {
		console.log("watch update:", value);
		resolve();
	});
});
```

注释概括了 watch 的三大保证：它从一次稳定的获取修订（revision）出发，因此先打印的 `notesWatch.value` 是一个一致的基线值；慢回调绝不重叠（同一时刻最多一个回调在执行）；精确的已提交帧会缓冲排队，缓冲满 100 帧后退化为一次"全量值重置"——宁可少投几帧细节，也不丢最终一致。`watchDoc()` 同样不创建文档，不存在时返回 undefined。`start()` 注册的回调可以是异步的；示例用一个 Promise 在首次投递时 resolve，方便主流程精确等待。

### 3. 触发、等待与停止

```ts
await session.commit(async (tx) => {
	(await tx.doc(Notes, chat.id)).text = "observed asynchronously";
}, context);
await delivered;
await notesWatch.stop();

await session.close(context);
```

在事务里把文档改成 "observed asynchronously"，随后 `await delivered` 等观察器真正收到这次变更，再 `notesWatch.stop()` 停止观察。与示例 04 不同，这里没有 `dispose()`——watch 的生命周期由 `stop()` 收尾。

## 关键点

- watch 与 04 的 subscribe 定位不同：它面向异步消费，核心保证是"回调串行执行、绝不重叠"，适合把文档变更排队喂给慢处理逻辑。
- 观察器从一次稳定的获取修订出发，启动基线 `notesWatch.value` 保证是某个一致的已提交状态。
- 变更帧会缓冲排队；超过 100 帧后退化为全量值重置，防止慢消费者无限积压。
- `watchDoc()` 是纯读端，不创建文档：不存在返回 undefined。
- `start()` 的回调是 async；配合 Promise 可以精确等待第一次投递，结束后调用 `await notesWatch.stop()`。
