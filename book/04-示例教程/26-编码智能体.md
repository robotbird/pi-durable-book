# 示例 26 · 编码智能体

> **原文**：[`test/examples/26-coding-agent.ts`](https://github.com/earendil-works/pi/blob/main/packages/durable/test/examples/26-coding-agent.ts)（在原仓库 `packages/durable` 目录下运行）
>
> ```bash
> node --conditions=source --experimental-strip-types test/examples/26-coding-agent.ts
> ```

## 本例演示

拼装一个最小的编码智能体：安装内置 `CodingTools`，配上应用自己的提示词段（静态 preamble 与动态 cwd 段），settings 全部用 getter 对接"用户随时会改的 settings.json"，环境工厂按对话的 `cwd` 构造执行环境。随后演示 `root.configure({ cwd })` 切换项目目录、直接改 `userSettings` 关闭并行工具——两者都无需重启、从下一次使用生效。

## 逐段解读

### 工作区与 Coding 扩展

```ts
import { mkdir, mkdtemp, rm } from "node:fs/promises";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { BACKGROUND_CONTEXT } from "@earendil-works/chord/context";
import type { ToolResultMessage } from "@earendil-works/pi-ai";
import { createModels } from "@earendil-works/pi-ai/models";
import { fauxAssistantMessage, fauxProvider, fauxToolCall } from "@earendil-works/pi-ai/providers/faux";
import { NodeExecutionEnv } from "../../src/env/node.ts";
import {
	createRegistry,
	defineExtension,
	Harness,
	type HarnessSettings,
	MemoryStorage,
	section,
	ToolResultEntry,
} from "../../src/index.ts";
import { CodingTools } from "../../src/tools/index.ts";

const context = BACKGROUND_CONTEXT;
const workspace = await mkdtemp(join(tmpdir(), "pi-durable-agent-"));
await mkdir(join(workspace, "app"));

// The app's own prompt, next to the coding tools.
const Coding = defineExtension({
	name: "coding",
	sections: [
		section("preamble", () => "You are a coding agent. Use the tools to inspect the project.", { tag: false }),
		section("cwd", (input) => input.env?.cwd),
	],
});
const registry = createRegistry();
registry.install(CodingTools);
registry.install(Coding);
```

先建一个临时工作区，里面再建一个 `app` 子目录，等下用来"切换项目"。注释说这是"应用自己的提示词，紧挨着编码工具"：`preamble` 段是静态文案，第三个参数 `{ tag: false }` 表示渲染时不包 XML 式标签；`cwd` 段是动态的——回调拿到的 `input.env` 是当前执行环境，取它的 `cwd`，目录一变这段提示就跟着变。`CodingTools` 从 `src/tools/index.ts` 导入，一次 install 就带来 read、bash 等内置编码工具。

### settings getter：像被 watch 的 settings.json

```ts
// Settings the user edits while the agent runs, like a settings.json the app watches. The getters make every
// Harness read see the current file; nothing is copied or stored.
const userSettings = { parallelTools: true, maxRetries: 3 };
const settings: HarnessSettings = {
	get toolExecution() {
		return userSettings.parallelTools ? "parallel" : "sequential";
	},
	get retry() {
		return { maxRetries: userSettings.maxRetries };
	},
};
```

注释点明意图：模拟"用户在 agent 运行期间编辑、应用正在 watch 的 settings.json"。关键是**所有配置项都写成 getter**：Harness 每次读取 settings 都会执行 getter、拿到 `userSettings` 的当前值——没有复制、没有快照。后面直接改 `userSettings.parallelTools` 就等于改了配置文件。

### 环境工厂：跟随对话目录

```ts
// The Harness calls this for every tool call and request with the conversation's `cwd`, so changing a conversation's
// directory needs no restart.
const env = ({ cwd = workspace }: { readonly cwd?: string }) => new NodeExecutionEnv({ cwd });
```

`env` 不再是一个固定实例，而是工厂：Harness 在**每次工具调用和每次请求**时，都用对话当前的 `cwd` 调用它。参数缺省落到 `workspace`——没有显式设目录的对话就在 workspace 里干活。注释给出结论：切换对话目录不需要重启。

### 伪造模型、Harness 与读取 bash 输出的辅助函数

```ts
const faux = fauxProvider();
const models = createModels();
models.setProvider(faux.provider);
const pwd = () => fauxAssistantMessage(fauxToolCall("bash", { command: "pwd" }), { stopReason: "toolUse" });
faux.setResponses([pwd(), fauxAssistantMessage("Done."), pwd(), fauxAssistantMessage("Done.")]);

const harness = await Harness.open(new MemoryStorage(), { models, registry, settings, env }, context);
const root = await harness.root(context, { agent: { model: { provider: "faux", modelId: "faux-1" }, cwd: workspace } });

const lastBashOutput = async () => {
	const page = await root.entries({}, 10, undefined, context);
	const result = page.items.find((entry) => ToolResultEntry.is(entry))?.model?.[0] as ToolResultMessage;
	return result.content.map((part) => (part.type === "text" ? part.text.trim() : "")).join("");
};
```

模型剧本是"调 bash 跑 `pwd` → 说 Done"两轮，重复两次，正好覆盖目录切换前后各一次。root 的 agent 配置里显式带了 `cwd: workspace`——对话级的工作目录。`lastBashOutput` 从最近的条目里找出第一条工具结果（`ToolResultEntry.is`），把其中的文本块拼起来——也就是 `pwd` 的输出，用来验证 bash 到底跑在哪个目录。

### 两次提问，一次切换

```ts
await (await root.submit({ type: "input", content: "Where are we?" }, context)).wait(context);
console.log("bash ran in:", await lastBashOutput());

// The user switches the project directory and turns off parallel tools. Both apply from the next use.
await root.configure({ cwd: join(workspace, "app") }, context);
userSettings.parallelTools = false;
await (await root.submit({ type: "input", content: "And now?" }, context)).wait(context);
console.log("bash ran in:", await lastBashOutput());

await harness.close(context);
await rm(workspace, { recursive: true, force: true });
```

第一次提问，bash 跑在 `workspace` 里。随后的注释说明这一步做了两件事——用户切换项目目录（`root.configure({ cwd })`）并关掉并行工具（直接改 `userSettings`），**两者都从下一次使用开始生效**。第二次提问，`pwd` 输出变成了 `.../app`，证明环境工厂按新目录重新构造了执行环境；工具执行模式也切换为 sequential。最后清理。

## 关键点

- `CodingTools` 是内置编码工具集合，`registry.install(CodingTools)` 一步装好 read/bash 等，再叠加自己的扩展。
- `section()` 支持动态回调：`section("cwd", (input) => input.env?.cwd)` 每次渲染都取当前执行环境的 cwd；`{ tag: false }` 让静态段不包 XML 标签。
- settings 全用 getter 就是活配置：Harness 每次读取都拿最新值，"改 settings.json 不重启"就是这么实现的。
- `env` 是工厂而非实例：每次工具调用/请求都以对话当前 cwd 重新构造执行环境，改目录不用重启。
- `root.configure({ cwd })` 在运行中切换对话目录，下一个工具调用立即在新目录里跑。
- 从对话条目里用 `ToolResultEntry.is()` 捞工具结果，是验证工具行为最直接的手段。
