# 示例 28 · 审查者

> **原文**：[`test/examples/28-reviewer.ts`](../../original/packages/durable/test/examples/28-reviewer.ts)（在 original/packages/durable 目录下运行）
>
> ```bash
> node --conditions=source --experimental-strip-types test/examples/28-reviewer.ts
> ```

## 本例演示

在主对话旁边开一个独立的"审查者"对话：更便宜的模型、审查角色提示词、用 `hook(GenerationTask, { onYield })` 实现的审查循环（还有发现就再来一轮，直到说出 DONE）、只有 read 一个工具、以及自己的项目 checkout（worktree）。审查者的全部身份配置存在它自己的对话上，重启不丢。

## 逐段解读

### 产品代码：审查者扩展与审查循环

```ts
import { mkdtemp, rm, writeFile } from "node:fs/promises";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { BACKGROUND_CONTEXT } from "@earendil-works/chord/context";
import type { AssistantMessage } from "@earendil-works/pi-ai";
import { createModels } from "@earendil-works/pi-ai/models";
import { fauxAssistantMessage, fauxProvider, fauxToolCall } from "@earendil-works/pi-ai/providers/faux";
import { NodeExecutionEnv } from "../../src/env/node.ts";
import {
	AssistantEntry,
	createRegistry,
	defineExtension,
	GenerationTask,
	Harness,
	hook,
	MemoryStorage,
	section,
} from "../../src/index.ts";
import { CodingTools, createReadTool } from "../../src/tools/index.ts";

const context = BACKGROUND_CONTEXT;
const textOf = (message: AssistantMessage) =>
	message.content.flatMap((part) => (part.type === "text" ? [part.text] : [])).join("");

// ─── Product code: the reviewer extension ───────────────────────────────────

const DONE = "No further findings.";
// A role and a review loop: every answer that still has findings gets a second pass.
const Reviewer = defineExtension({
	name: "reviewer",
	sections: [section("role", () => `You review diffs. Report problems as a list. Never edit files.`)],
	hooks: [
		hook(GenerationTask, {
			onYield: (answer) =>
				textOf(answer).includes(DONE)
					? undefined
					: { continue: `Look again for anything you missed. Say "${DONE}" when there is nothing left.` },
		}),
	],
});
```

`textOf` 把 AssistantMessage 的文本块拼成字符串。注释概括扩展的两部分内容：一个角色（审查 diff、以列表报告问题、**绝不改文件**），加一个**审查循环**。循环通过 `hook(GenerationTask, { onYield })` 挂在生成任务上：模型每次产出（yield）一段回答，`onYield` 就检查一次——不含 `DONE` 哨兵句就返回 `{ continue: 指令 }`，把"再找找有没有漏的，找完就说出 No further findings."作为下一轮的提示；含了就返回 `undefined` 放行、本轮结束。

### 宿主：大模型主对话与审查者的 worktree

```ts
// ─── Host setup ─────────────────────────────────────────────────────────────

// The reviewer works in its own checkout, in practice a `git worktree add`.
const worktree = await mkdtemp(join(tmpdir(), "pi-durable-review-"));
await writeFile(join(worktree, "user.ts"), "export const name = (user) => user.name;\n");

const faux = fauxProvider({ models: [{ id: "big" }, { id: "small" }] });
const models = createModels();
models.setProvider(faux.provider);
faux.setResponses([
	fauxAssistantMessage(fauxToolCall("read", { path: "user.ts" }), { stopReason: "toolUse" }),
	fauxAssistantMessage("1. `name` does not handle a missing user."),
	fauxAssistantMessage(`2. \`user\` has no type. ${DONE}`),
]);

const registry = createRegistry();
registry.install(CodingTools);
registry.install(Reviewer);
const harness = await Harness.open(
	new MemoryStorage(),
	// The main agent selects only CodingTools; the reviewer opts in.
	{
		models,
		registry,
		settings: { extensions: [CodingTools] },
		env: ({ cwd = process.cwd() }) => new NodeExecutionEnv({ cwd }),
	},
	context,
);
await harness.root(context, { agent: { model: { provider: "faux", modelId: "big" } } });
```

注释交代审查目录的实际含义：生产里通常是一条 `git worktree add`，这里用临时目录加一个有问题的 `user.ts` 模拟。模型注册了 big / small 两个型号；剧本三步——`read user.ts`、第一轮发现（没有 DONE，会被循环打回）、第二轮发现加 DONE（循环退出），正好演示"每个还有发现的回答都会再来一遍"。settings 行的注释与 26 例同款：主 agent 默认只选 CodingTools，Reviewer 由审查者对话自己 opt-in。`harness.root()` 用 big 模型开出主对话——本例里它不参与对话，只是衬托"审查者挂在主对话旁边"的架构位置。

### 一切身份都存在对话上

```ts
// Everything the reviewer is, stored on its conversation: the model, exactly these extensions in this order, only
// the read tool, and its directory. A restart keeps all of it.
const reviewer = await harness.createConversation(
	{
		ownership: { kind: "ownerless" },
		agent: {
			model: { provider: "faux", modelId: "small" },
			extensions: [CodingTools, Reviewer],
			tools: [createReadTool()],
			cwd: worktree,
		},
	},
	context,
);
const agent = await reviewer.agent(context);
console.log(
	"reviewer:",
	agent.model?.modelId,
	agent.extensions.map((extension) => extension.name),
	agent.tools.map((tool) => tool.name),
	agent.cwd === worktree,
);
```

注释是本例的题眼：审查者"是什么"全部存在**它自己的对话**上——small 模型、按顺序排列的 `[CodingTools, Reviewer]` 两个扩展、只有 read 一个工具、以及自己的目录 `cwd`。这些配置随对话持久化，**重启后原样恢复**。`createConversation` 用 `ownership: { kind: "ownerless" }` 建一个不挂在任何宿主 root 下的独立对话。`reviewer.agent(context)` 在运行时解析出实际生效的模型、扩展名、工具名和 cwd，打印出来验证四项都符合预期。

### 提交审查并回放

```ts
await (await reviewer.submit({ type: "input", content: "Review user.ts." }, context)).wait(context);
const page = await reviewer.entries({}, 20, undefined, context);
for (const entry of [...page.items].reverse()) {
	const message = entry.model?.[0];
	if (message?.role === "user") console.log(">", message.content);
	if (AssistantEntry.is(entry) && textOf(message as AssistantMessage) !== "") {
		console.log("reviewer:", textOf(message as AssistantMessage));
	}
}

await harness.close(context);
await rm(worktree, { recursive: true, force: true });
```

给审查者派活并等它跑完（一次 read、两轮发现）。`entries` 返回的页是**新到旧**排序，`reverse()` 后按时间顺序回放：打印用户指令和每段非空的助手回答——输出里能看到第一轮 "1. `name` does not handle a missing user." 和第二轮 "2. `user` has no type. No further findings."，证明审查循环确实让模型多答了一轮才收工。最后清理临时目录。

## 关键点

- 审查循环 = `hook(GenerationTask, { onYield })`：检查每次产出，返回 `{ continue: 指令 }` 追加一轮、返回 `undefined` 放行；DONE 哨兵句是退出条件。
- 角色提示词（"只报告、绝不改文件"）与只给 read 工具双管齐下，保证审查者只读不写。
- 对话级 agent 配置（模型、扩展及其顺序、工具、cwd）随对话存储，重启后原样生效。
- `createConversation({ ownership: { kind: "ownerless" }, agent: {...} })` 创建独立的辅助对话，不挂在宿主 root 之下。
- 宿主默认只选 CodingTools；Reviewer 由审查者对话自行加入——同一注册表服务不同角色的对话。
- `entries()` 按新到旧返回，回放对话要 `reverse()`；`AssistantEntry.is()` 用来筛出模型回答。
